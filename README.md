自动更新iptv节目内容

这是一个基于 GitHub Actions 的 IPTV（网络电视）直播源自动抓取、校验、去重和更新脚本。从名称“(Fusion Edition)”和代码逻辑可以看出，它融合了多种处理逻辑，旨在打造一个高可用、防误杀的直播源列表。

以下是该源码的核心功能详细拆解：
1. 自动化定时调度
定时执行：通过 cron: '0 */6 * * *'，每天自动运行 4 次（每 6 小时一次），保证直播源的时效性。
手动触发：支持 workflow_dispatch，方便在需要时随时手动强制运行。
自动部署：拥有仓库写入权限（contents: write），运行完毕后会自动将结果 Git Commit 并 Push 回仓库。

2. 多源聚合与智能格式统一（第一步）
多源抓取：内置了 23 个不同的 IPTV 源地址（包含 IPv4 和 IPv6 源，如 Guovin、Fanmingming、YueChan 等），实现大范围聚合。
容错机制：使用 || true 和超时设置（15秒连接，30秒最大读取），确保单个源挂掉不会导致整个脚本崩溃。
智能格式识别：
M3U 格式识别：检测到 #EXTINF 标签时，自动提取频道名、直播地址和分组名（group-title 或 #EXTGRP）。
TXT 格式识别：对普通文本格式进行兼容处理，补齐缺失的分组列。
统一中间格式：将所有来源的数据统一转化为 频道名,直播地址,分组名 的三列标准格式，为后续去重和分类打下基础。

3. 精准去重（第二步）
按行去重：使用 awk 'NF && !seen[$0]++'，不仅去除了完全相同的重复行，还顺带清理了空行（NF 保证了不含空行），精简列表体积。

4. 防误杀并发验证（第三步，核心亮点）
这一步是保证直播源“可用性”的关键，融合了多重防误杀和加速策略：
高并发测速：使用后台进程（&）和 jobs 计数，维持 15 个并发 同时验证，极大缩短了成百上千条链接的检测时间。
Range 请求（防误杀）：使用 -r 0-1024 请求流媒体的前 1KB 数据，而不是用简单的 HEAD 请求或下载全量。因为很多流媒体服务器不支持 HEAD 请求，但支持 Range，这样既省流量又防误杀。
伪装请求头：注入了主流浏览器的 User-Agent 和对应的 Referer，防止被源站的反爬机制拦截。
失败重试机制：首次验证失败后，会休眠 1 秒再重试一次，避免因网络波动导致的漏判。
忽略证书校验：使用 -k 参数，兼容部分证书过期或自签名的源站。

5. 标准化分组与分类输出（第四步）
转换为国产软件格式：将中间格式转化为国内常见 TV 软件兼容的格式：先输出 分组名,#genre# 作为分类头，接着输出该分类下的 频道名,直播地址。这种格式可以直接被影视仓、DIYP 等软件识别。
智能拆分文件：
live.txt：包含所有有效频道的总表。
CCTV.txt：专门提取出包含 "CCTV" 关键词的央视频道。
Satellite.txt：专门提取出包含 "卫视" 关键词的省级卫视频道。

总结
这套脚本的核心价值在于：它不仅仅是一个简单的爬虫，而是一个带有“质量把控”的流媒体处理流水线。 它把互联网上参差不齐、格式各异、死活不定的各种 IPTV 源，通过“抓取 -> 标准化 -> 去重 -> 存活性校验 -> 分类输出”的流程，最终生成了一份干净、有效、即开即看的直播源列表。
